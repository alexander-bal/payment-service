  with real commits on a throwaway branch, which I've since deleted. Clean
  changes got through and broken ones were blocked. I found three false
  positives along the way and fixed them all.

  Files (left uncommitted on main):
  - Gemfile / Gemfile.lock: adds lefthook 2.2.2 to the development/test group.
  - lefthook.yml: the pre-commit hook runs script/pre-commit-ci.
  - script/pre-commit-ci: copies exactly what you staged to
    .git/pre-commit-snapshot, along with config/master.key, and runs bin/ci
    there. The copy is deleted afterwards.
  - .git/hooks/pre-commit: installed by lefthook. It isn't tracked by git.

  Why the wrapper is needed. Running plain bin/ci gave wrong results in two
  cases, because rubocop checks everything on disk, not just what's staged:
  - New files you haven't added: a broken new file blocked an unrelated README
    commit.
  - Edited files you haven't staged: a broken payment.rb blocked a README
    commit. Lefthook only hides unstaged edits in files that are partly staged.

  My first fix moved those files out of the way during the run. That was unsafe:
  on Ctrl-C lefthook force-kills the job, so the files never got put back. In
  my test, a modified file and a deleted file were stranded until I restored
  them by hand. The final version never touches your files.
